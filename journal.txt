 J3 
 intialisation de l'API avec connexion à la base de données 
 Architecture FastAPI avec separation en routers pour scalabilité pour alléger le main 
 
 On avait pensé à une utilisation de async avec pool de connexion mais ca bloquait avec windows les tests étaient pas fonctionnels

 SOLUTION : Passage en mode synchrone (ConnectionPool classique)
 - Remplacé AsyncConnectionPool par ConnectionPool (psycopg3 version synchrone)
 - Suppression de tous les async def, await, asynccontextmanager
 - Endpoints redeviennent fonctions simples (non-async)
 - Lifespan remplacée par add_event_handler("startup") / add_event_handler("shutdown")
 - Résultat : 7 tests passent instantanément, aucune dépendance event loop
 
 Endpoints implémentés :
 GET /health : vérification simple de la connexion à la base de données (retourne 503 si indisponible)
 GET /api/v1/oni : liste complète des observations triées par date_centrale croissante
 Filtres de date : paramètres optionnels debut et fin (YYYY-MM-DD format) avec validation FastAPI,
 requête SQL dynamique avec WHERE clause et paramètres sûrs (psycopg3 autoescaping)
 

 Tous les tests passent en 4.03s avec pytest, aucune configuration complexe requise
